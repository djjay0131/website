## The Skeptic's pre-seeded portrait: gate FAIL or not?

**Verdict: NOT a FAIL for this wave — non-blocking follow-up.**

Reproduced with evidence. Place a portrait into `dist-public` **after** the build
and before a hypothetical deploy:

```
$ cp src/content/sources/cv/cv-data/photo_jason_1.jpeg dist-public/photo_jason_1.jpeg
$ npm run check:no-private-in-public
 check:no-private-in-public: PASS — … (163 files scanned).        EXIT 0   # not refused
$ npm test
 Test Files 23 passed | Tests 295 passed | 1 skipped              EXIT 0   # not caught
$ rm -f dist-public/photo_jason_1.jpeg
```

Why this is not a Wave 0c gate FAIL:

1. **The delivered artifact satisfies the check.** Check 3 is an *absence* test on
   the built output ("not staged to `dist-public` and not referenced by any
   `og:*` tag"), and C1 asserts no private content on the built public path. After
   `npm run build:public` there is **no** `photo*` file in `dist-public` (162
   files), and every `og:*` tag is `og-card.png`. Both requirements hold.
2. **A pre-seed does not survive the pipeline.** Astro cleans `outDir`, and the
   branch's own guards delete a stale `public/photo_jason_1.jpeg` at
   `config:setup`. Verified twice: pre-seeding `dist-public/photo_jason_1.jpeg`
   then `npm run build:public` → file **GONE**; pre-seeding `public/` → deleted
   before copy (Skeptic Demo 4 positive control). The un-refused case therefore
   requires an **out-of-band write to `dist-public` after the build**, i.e. a step
   outside the build the wave owns and outside what the gate can observe.
3. **Scope of the guard.** `check:no-private-in-public` matches private *manifest
   items*; a portrait is neither a slug/source/title/summary nor a private item,
   and the check's own LIMITS section states binaries are matched by path only.
   This is the documented boundary, not a Wave 0c regression — the portrait has
   no matching needle.

Follow-up (Fix now, non-blocking): add a forbidden-output-path assertion to
`check-no-private-in-public.mjs` (fail on any `dist-public/**/photo_jason_1.jpeg`
or portrait-named file) so the guard is fail-closed rather than build-order
dependent. This matches the Skeptic Verifier's Demo 4 finding; it is a hardening
of the leak check, not a defect in the Wave 0c build output.
