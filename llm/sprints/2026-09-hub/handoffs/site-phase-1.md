## Summary

The Astro site under `site/` now builds for the new host at base `/` by
default (`https://cusati.us`). With `SITE_URL=https://djjay0131.github.io
SITE_BASE=/website/` it builds for GitHub Pages. Every route the current site
serves keeps its URL and content, and the build adds three shells: `/cv/`,
`/writing/` and `/phd/`.

- **D1 Host-agnostic URLs (SEAM-1).** `astro.config.mjs` reads `SITE_URL` and
  `SITE_BASE` through `scripts/site-env.mjs`. An empty variable takes its
  default, a base is normalized to `/x/`, and a `SITE_URL` that carries a path
  fails the build. Output is static in `dist-public/`, with no adapter. The four
  legacy `redirects` live in `scripts/site-routes.mjs` as base-relative paths,
  and their targets get the configured base added. The two hardcoded
  `djjay0131.github.io/website` JSON-LD URLs on the CV page now derive from
  `Astro.site` and the base. `public/robots.txt`, which hardcoded the Pages
  sitemap URL, is replaced by the endpoint `src/pages/robots.txt.ts`. A default
  build contains no `/website/` anywhere.
- **D2 Design system.** `src/styles/tokens.css` defines Spectral, IBM Plex Sans
  and IBM Plex Mono, with the petrol accent `#0F5C5A`, brass (caution) and clay
  (risk). It has complete light and dark palettes, switched by
  `prefers-color-scheme` with no JavaScript. Fonts are self-hosted from
  `@fontsource/*` 5.3.0 (OFL-1.1) and bundled into `/_astro/` under the base.
  Base.astro's old palette is gone, as are every literal colour in the pages
  and the research SourceExplorer. `scripts/contrast.mjs` plus
  `src/styles/tokens.test.ts` fail the tests if any text pair drops below
  4.5:1.
- **D3 Layouts.** `Base.astro` covers the head, navigation, footer and tokens.
  `SectionIndex.astro` shows a title, lede, and an item list or an empty
  state. `ItemPage.astro` shows a title, date and metadata, the body and a back
  link. Every page renders inside Base. `/research/`, `/projects/`, `/cv/`,
  `/writing/` and `/phd/` use SectionIndex, and `/projects/<slug>/` uses
  ItemPage.
- **D4 Section shells.** The navigation reads Research · Projects · Writing ·
  CV, then Papers · Resumes. It never links phd, and no built page links
  `/phd`. `/phd/` is an empty state with `<meta name="robots"
  content="noindex">` and is left out of the sitemap by a filter in
  `astro.config.mjs`.
- **D5 `firebase.json`** (repository root). It has `public: site/dist-public`,
  the design doc §8 `ignore` and headers, `cleanUrls: false` and
  `trailingSlash: true`. It has no `rewrites`, functions or framework backend.
- **D6 Redirect map (SEAM-6).** `site/redirects/github-pages.json` has 48
  entries, generated by `scripts/generate-redirect-map.mjs` (`npm run
  redirects:generate` or `redirects:check`). The script builds the Pages variant
  and inventories it with `scripts/route-inventory.mjs`.
  `scripts/route-inventory.test.ts` fails when the map misses or misdirects an
  inventoried route.
- **D7 CV data (SEAM-2).** `scripts/fetch-data.sh` reproduces the inline
  `build.yml` step byte for byte; `diff -r` found no differences.
  `scripts/sync-local-data.sh` works from `site/`, with its default cv path now
  `../../cv`. `.vscode/launch.json` starts the dev server with `cwd`
  `${workspaceFolder}/site`.

## Verifier findings (remediation round 1)

One should-fix finding (SEAM-1, SEAM-2) was applied:

- **The problem.** `src/lib/cv-data.test.ts` pinned exact counts from the
  fetched CV data (employment 6, education 3, projects 4, skills 4). Once the
  `cv` repository publishes data like the owner's newer local copy, the first
  "Run tests" step in CI would fail and block both deploys. The test predates
  Phase 1.

  fixture, `site/src/lib/__fixtures__/cv/` (8 content files, 2 variants and a
  README). All names, ids and values in it are invented. The fixture tests
  also cover what the old test did not: bullet filtering and reordering, role
  collapse, skill-item subsetting, an unknown bullet id, and that the pool
  itself stays unchanged.
- **Kept on the fetched data (SEAM-2), structure only.** The content pool
  loads with a name and contact email. Every variant has a label. Every
  variant in `site/data/variants` resolves, keeps the section order from its
  file, and resolves one entry per `include` item for employment, education,
  projects and skills. None of these checks pin a count, id or name.
- **The baseline failure is gone.** `npm test` now passes on both the owner's
  local data and the current release data.
- **Contract conflict, recorded.** The contract's Validation section said "Do
  not modify that test". The Lead Architect's remediation instruction
  overrides that for this finding. `site/data/` was not touched.

## Assumptions

- The four legacy redirect sources stay as-is, and trailing-slash targets are
  acceptable.
- A route is a base-relative URL path. The redirect map lists pages in
  trailing-slash form only, since both hosts 301 the slashless form.
- The files CI adds to `public/` (`build-info.json`, the photo, one PDF per CV
  variant) are part of what the Pages build serves.
- `/_astro/` hashed assets are not routes for redirect purposes.
- `/phd/` belongs in the map, because the Pages build serves it.
- `npm test` must not depend on the CV release's project or variant list, or
  on any count in the CV data. See Risks and seam issue 1.
- CI always fetches CV data before `npm test`. The structural checks in
  `cv-data.test.ts` (like `bib.test.ts`) still need `site/data/` present, as
  the old test did.

## Alternatives considered

- **Inventory routes from `src/pages` alone, with no build.** Rejected as the
  generator source: dynamic routes would need Astro's routing re-implemented.
  It is kept as the hermetic check inside `npm test`.
- **Check the committed map against the build on every `npm test`.**
  Rejected: CI runs `npm test` after a build, so a new `cv` project would fail
  the pipeline and block deploys. It is opt-in instead
  (`REDIRECT_MAP_CHECK_BUILD=1`).
- **Emit both slash and slashless map entries.** Rejected as noise; coverage
  normalizes instead.
- **`cv-data.test.ts`: structural checks only on `site/data`, with no
  fixture.** Rejected as the only change. Structure alone cannot test the
  exact behaviour of the resolver's selectors (bullet order, collapse, item
  subsets). The fixture pins that behaviour, and the structural checks keep
  SEAM-2's fetched data under test. Also rejected: skipping the data tests
  when `site/data` is absent, because that would hide a failed fetch.
- **Leave `trailingSlash` unset.** Superstatic behaves the same for this site,
  but the contract asked for deliberate settings, so it is set explicitly.
- **`cleanUrls: true`.** Rejected: it adds redirects for `*.html` and gains
  nothing with Astro's directory output.
- **Google Fonts or another CDN.** Excluded by the contract (self-hosting).
- **A `[data-theme]` attribute with a toggle script.** Excluded: ADR-0003 wants
  zero JavaScript by default.
- **Keeping the old variable names (`--color-primary`, `--font-sans`,
  `--font-serif`) as aliases.** Rejected: that would carry the ad hoc palette's
  names forward. They were renamed in the pages instead
  (`--color-link`, `--font-body`).
- **Building the Pages variant into the OS temp directory.** Failed with
  `EXDEV` when the checkout and the temp directory are on different
  filesystems, because Astro renames files out of `site/.astro`. The generator
  builds under `site/node_modules/.cache/` (gitignored) and removes the
  directory afterwards.

## Risks

- **Data-dependent map entries.** The committed map's project and CV entries go
  stale when the `cv` release changes. `npm test` does not catch it (by
  design); `redirects:check` does.
- **Superstatic is not production Hosting.** URL behavior is confirmed only at
  Checkpoint 2.
- **Visual regressions** in pages I did not open in a browser, especially dark
  mode in the research source explorer (chips, filters, flash highlight).
  Contrast is tested; layout is not.
- **Smoke routes duplicated.** `scripts/site-routes.mjs` repeats the
  `build.yml` smoke-test route list (infra-owned) and can drift from it.
- **A misconfigured `SITE_URL`** (one with a path) fails the build loudly. That
  is intentional.
- **CV-release-dependent tests (resolved in remediation round 1).** The old
  `cv-data.test.ts` pinned counts from the CV data and would have blocked both
  deploys at the next `cv` release with a changed academic variant. It now
  runs on a fixture, and a structural check on the fetched data fails only on
  malformed data (an unknown id, a broken variant). A malformed release is a
  real defect, and it would fail the build anyway.
- **`bib.test.ts`** still reads `data/own-bib.bib`. Its assertions are
  structural apart from "an entry authored by Cusati", which is stable. It is
  not in the finding and was not changed.

## Seam issues

1. **SEAM-1 and SEAM-6 under CI order.** The new `build.yml` runs `npm test` for
   the Firebase variant after the Pages build has left `site/dist-public` in
   place. Tests that inspect `dist-public` would then run in CI against release
   data. I made that test opt-in. No change is needed in `build.yml`; this is
   recorded for reconciliation.
2. **SEAM-6 does not say how data-dependent routes are kept current.** The map
   is a snapshot of the CV data at generation time.
3. **SEAM-3 covers no 404 page** (Recommendation 1).
4. **The smoke-test routes have no single source** shared by `build.yml` and
   the site's route inventory.
5. **SEAM-2.** `fetch-data.sh` uses a `mktemp` directory rather than
   `/tmp/cv-fetch`. The files under `site/` are identical (verified). It does
   not write `build-info.json`, per SEAM-2.

## ADR candidates

- **Self-hosted fonts** from `@fontsource` npm packages, never a runtime CDN
  (subset policy included).
- **Theme switching** by `prefers-color-scheme` only, with no toggle and no JS.
  Tokens are the only colour source, and a test enforces AA contrast.
- **Canonical URL form:** trailing-slash directory URLs, with `trailingSlash:
  true` and `cleanUrls: false`, matching GitHub Pages.
- **Redirect-map lifecycle:** generated from a build inventory, a snapshot in
  Phase 1, regenerated when served in Phase 6. Also, whether unlinked and
  noindex sections (`phd`) are listed.
- **Host-agnostic build:** `SITE_URL` and `SITE_BASE` validation, and never
  writing a base into page code.
