Setup

An open agent loop (OpenCode) runs inside a sandbox and reaches models only through a gateway we own. A separate verifier grades each patch on a fresh copy with tests the agent never sees. Tasks are synthetic: ten routine changes to a small Python service and three harder ones written to defeat the obvious solution. Models are open-weight, served from a shared university endpoint.

Pass rates

Task setSmall model firstMid-size model firstLargest open model only
Routine (10 tasks)10 of 10, no escalation10 of 10, no escalation7 of 10
Hard (3 tasks, 3 seeds)8 of 9, 4 escalations9 of 9, no escalation2 of 3 (1 seed)

The largest model's misses were mostly timeouts. On this endpoint its problem was latency, not wrong answers.

Cost

Estimated serving cost per verified task, at 50 percent utilisation, on assumed hardware:

Task setSmall firstMid-size first
Routine$0.022$0.040
Hard$0.097$0.070

Three things follow.

  1. Model size is the cost lever. Cost per task scales with the GPUs a model needs, and the smallest model that passes verification wins.
  2. Hosting is not. Our estimate for serving an open model ourselves lands near or above that model's hosted API price. The reason to host is control over data and change, not unit cost.
  3. Routing needs a difficulty signal. Small-first was cheapest on routine work and most expensive on hard work, because failed first attempts are paid for. Escalation rescued every failure, so the safety net works. Knowing when to skip the small model is the open problem.

Controls that held

  • A hash-chained audit log that detects a one-line edit.
  • Approval bound to the exact patch, base, checks and policy revision; a one-byte change is refused.
  • Governance levels as policy: a higher-risk change is held to the strong tier and to owner approval, and a patch that passes its tests but files a design document in the wrong place fails verification.
  • Optional network isolation: the agent reaches the gateway and nothing else.
  • A plan loop for larger work: six dependent features built and verified in order, each on the verified result of the last.

Limits

One language, one small service, tasks we wrote. Hardware figures are assumptions. No frontier model was run on these tasks, so any comparison with hosted frontier prices is a price comparison, not a measured saving. Network isolation was shown on one host.
